# 鏡外 英語翻訳リファレンス

> YAML / CSV の翻訳時に参照する制作資料。
> GitHub Pagesの実行時データとしては使用せず、英語版の表記統一と翻訳品質の維持を目的とする。

## 1. 最優先の翻訳手順

翻訳時は、原則として次の順序で確認する。

1. 本リファレンスの「固定訳一覧」を確認する。
2. Characters / Works / Songs などのCSVを一次データとして確認する。
3. 既存のYAMLや他ページに確定済みの英語表記がないか確認する。
4. 既存訳がある場合は、それを優先して使用する。
5. 本リファレンスにも既存データにも英語表記が存在しない新規固有名詞・重要用語については、独断で正式訳を確定しない。先に制作者へ確認する。
6. 神話・古典・宗教などに由来する固有名詞・用語については、必要に応じて國學院大學の日本神話関連データベース等の信頼できる研究資料を参照し、読み・表記・由来を確認する。ただし、外部資料の表記を機械的に採用せず、本サイトで確定した固定訳との整合性を優先する。
7. 固定訳を確認したうえで、文脈・語り手・言葉遊び・文化的ニュアンスに応じた自然な英文へ再構成する。

**固定訳の正確さと、文章としての自然さは別々に扱う。**
固有名詞や世界観用語は勝手に意訳せず、文章構造や説明方法については英語圏の読者に意味が成立するよう柔軟に再構成する。

## 3. キャラクター性・文章表現の翻訳方針

### 3.1 直訳ではなく、機能とニュアンスを再構成する

日本語の表現を一語ずつ英語へ置き換えることを目的にしない。

優先するのは、英語版の読者が原文の読者と同じように、

- 設定上の意味
- 語同士の関係
- 言葉遊び
- 皮肉や含み
- キャラクターの感情
- キャラクターの話し方
- 日本語特有の文化的ニュアンス

を理解できることである。

日本語側で成立している仕掛けを英語側でも成立させるために、文章構造や説明順序を変更してよい。

### 3.2 言葉遊び・多義語

日本語の多義語や同音異義語が設定・台詞・用語体系に関係する場合、単純な直訳で失わない。

必要に応じて、

- 英語側で意味を明示する注釈を加える
- 日本語の語をローマ字等で残す
- 別の英語表現へ再構成して同じ言葉遊びの機能を持たせる

などを行う。

例：「あらわす」は日本語では複数の漢字表記を持つため、文脈によって意味が変わる。一方、『鏡外』の能力名では一貫して **Embodies** を用いる。この事実を必要に応じて英語版でも説明する。

### 3.3 キャラクターの「演技」を翻訳する

キャラクターが幼いのではなく、幼さ・可愛らしさ・甘ったるさなどを**意図的に演出している**場合、単純な幼児語へ置き換えない。

英語版では、原文の目的に応じて、例えば次の要素を組み合わせて同等のキャラクター性を再構成する。

- 語尾の引き伸ばし
- 過剰に親しげな呼称
- 自分の名前を一人称として使う表現
- わざとらしい可愛らしさ
- 甘ったるい、芝居がかった言い回し
- 少し「痛々しい」ほどのコンセプト感

日本語の「〜さん」のような表現を、必ずしも英語で一対一対応させる必要はない。重要なのは、**その呼び方が作っているキャラクター性を英語側で再現すること**である。

例：天照宮ひめの「天才さん」は、単なる丁寧な呼称ではなく、属性名に敬称を付けて可愛らしく扱う、甘ったるく演出的な呼び方として解釈する。英訳では文脈に応じて `dear Genius` のような再構成を検討できるが、これを固定訳として扱わない。

### 3.4 比喩体系を保つ

世界観内で特定の語彙群が一つの比喩体系を形成している場合、各単語を個別に直訳して体系を壊さない。

例：「メモランダムを著す／読む／正す」は、弾幕そのものではなく **Memorandum** を目的語とする表現である。

- **to write a Memorandum** → そのMemorandumのdanmakuを展開する
- **to read a Memorandum** → そのMemorandumのdanmakuに挑む
- **to correct a Memorandum** → そのMemorandumのdanmakuを避けきる

これらは、執筆・読解・校正／校了の語彙を、Memorandumとの戦闘行為へ比喩的に転用した表現である。

英語版では、個々の動詞の逐語対応よりも、**この比喩体系そのものが読者に理解できる構成**を優先する。

### 3.5 神通力の説明における「著す」

「メモランダムを著す」の「著す」は、能力名などで使われる多義語の「あらわす」ではなく、Memorandumを著作するという比喩表現である。

したがって英訳では **to write a Memorandum** を基本とし、`embody` / `embodies` には置き換えない。

文脈上、弾幕を放つこととの関係を明示する必要がある場合は、`to write Memorandums, that is, to unleash danmaku` のように再構成できる。

### 3.6 桜花の口調

桜花は、書物の付喪神・生き字引としての知的で論理的な性格とは対照的に、語尾を伸ばした、幼くのんびりした印象の話し方をする。この特徴は完全な口癖ではなく、本人が自分を幼く、のんびりした人物として見せるために、やや意図的に演出している側面がある。

そのため、桜花の日本語台詞に現れる「ー」を英語で機械的に `~` へ置換してはならない。`~` は英語圏でもチャット、漫画、ゲーム等のカジュアルな表現として語尾の引き伸ばしや甘さ・柔らかさを示すために使われるが、一般的な英文ではなく、使用すると漫画的・ネット的な印象が強くなる。

英訳では、まず桜花の**幼く、のんびりした、余裕のある話し方**を英語として自然な語彙・文のリズム・文末表現によって再構成する。そのうえで、語尾を伸ばしていること自体が台詞の演出として重要な場合には `~` を使用してよい。

つまり、原文の「ー」を記号として翻訳するのではなく、**桜花が意図的に作っている話し方そのものを翻訳する**ことを優先する。

また、桜花は穏やかで丁寧な話し方を保ったまま、相手の行動を淡々と評価したり、皮肉を述べたりすることがある。強い罵倒や露骨な悪口へ変換せず、**知的・丁寧・のんびりした口調と、内容の辛辣さとのギャップ**を維持する。

特に「雑ですねー」「暇な人ですねー」「趣味が悪いんですねー」のように、相手の行動を淡々と分類・評価して切り込む台詞では、英語側でも穏やかな語調を保ちながら、論理的に相手を追い詰める構造を活かす。

桜花が真剣な場面で語尾を伸ばし忘れることがあるという設定も考慮し、英訳では `~` を常用しない。普段の演出と緊張時の変化が区別できるよう、必要な場面だけ `~` を用いる。

## 4. 固有名詞・新規用語の追加ルール

### 4.1 既存の固有名詞

Characters / Works / Songs の名前そのものは、それぞれのCSVを一次データとする。

既存の英語表記がある場合は、本リファレンスの表記と合わせて使用する。姓・名の順序、`no` の有無、長音・ダイアクリティカルマーク等も勝手に変更しない。

### 4.2 未登録の固有名詞

本リファレンスにもCSVにも確定した英語表記がない固有名詞について、勝手に正式訳を追加しない。

候補を考えること自体は可能だが、**正式訳として採用・記録する前に制作者へ確認する**。

特に次のようなものは確認対象とする。

- 新しい人物名
- 新しい組織・施設名
- 新しい地名
- 新しい作品名
- 世界観固有の概念名
- 既存語を特別な意味で用いる新語

### 4.3 固定訳と個別の翻訳表現を分ける

本リファレンスの固定訳一覧には、作品全体で一対一対応させる必要がある用語だけを登録する。

一方、特定の台詞や文脈のために考案した表現は、固定訳にしない。

例：

- **神通力 → Jintsūriki** は固定訳。
- 「天才さん → dear Genius」は、ひめの台詞の翻訳上の再構成であり固定訳ではない。

## 5. 既存用語との整合性

翻訳する際は、単独の文章だけを見て訳語を決めない。

同じ人物・組織・地名・概念が別のCSV/YAML/Glossary項目に存在する場合、それらを突き合わせてから訳す。

特に、

- 人名の姓・名順
- 組織名の構成要素
- 地名の接尾語
- 宗教・役職用語
- 能力名の定型表現
- 同じ日本語の複数の用例

については既存データとの一致を優先する。

## 6. 追加・更新の運用

新しい正式訳が制作者によって確定した場合は、必要に応じて本リファレンスへ追加する。

追加時には、可能な限り次の情報を記録する。

- 日本語表記
- 英語表記
- 分類
- 文脈による使い分け
- 固定訳か、翻訳方針上の注意か
- 関連する既存用語

このファイルを、翻訳に関するルールと固定訳の**正本（single source of truth）**として扱う。
